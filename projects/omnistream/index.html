Database design / Coursework

OmniStream Database Project

A PostgreSQL coursework project that works through the structure and behaviour of a video-streaming database.

Source repository ↗

Focus

Relational design
Analytical SQL
Transactions

Make the relationships explicit.

The schema covers users, plans, subscriptions, payments, invoices, movies, genres, watchlists, viewing history and reviews. Keys and constraints establish relationships; seed data supplies an inspection environment.

The SQL explores joins, aggregation and JSONB metadata, including a GIN index. The design report discusses normalization. No measured performance study is included, so the index is presented as an implementation choice rather than a proven speedup.

A failure with a purpose.

A deliberately invalid invoice insert demonstrates a foreign-key failure and transaction rollback. That example is not a production migration. The ordered DDL and seed scripts provide the clearer route to recreating an example database.

Repository structure

sql/DDL.sql defines tables and constraints; sql/DML.sql supplies example data; sql/DQL_and_TCL.sql contains analytics, index creation and the rollback demonstration. Reports and editable diagrams are under docs/.

Scope

This is coursework, not a deployed streaming platform. The checked-in backup's restoration has not been independently verified here. No production scale, latency or commercial use is claimed.
