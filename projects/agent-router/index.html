Competition project / Prompting baselines

Huawei LLM Agent Router

Exploring how a local language model selects a tool from a Chinese-language request.

Source repository ↗

Tools

Python
Qwen3
PyTorch / Transformers

One decision, two approaches.

The runnable baseline compares a direct tool prompt with a hierarchical category-then-tool prompt. Both produce a proposed function-call string. Neither executes device actions.

The repository includes tool metadata, synthetic examples, evaluation scripts and offline routing/parser checks. The runnable implementation is core/demo_agent.py; core/agent.py remains an unfinished competition template.

Correct name, incorrect call.

One historical 50-case run records 17 exact-string matches and 47 function-name matches. That gap matters: choosing the right function does not establish correct arguments or safe execution. These are historical run counts, not a general benchmark.

Current boundary

The baseline parses text between tool tags with a regular expression. It does not validate calls against a schema or check argument types. Historical metrics predate a conversation-context evaluation fix and are not a validated multi-turn benchmark.

Run and inspect

Offline unittest checks do not need model weights. Running a baseline requires a local Qwen3-compatible model and packages appropriate for the hardware. Model weights are not included. The historical environment export is not a portable installation specification.
